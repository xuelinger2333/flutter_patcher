# Ed25519 verification

`Ed25519Verifier.kt` implements verification only, following RFC 8032 sections
5.1.3, 5.1.4 and 5.1.7. It uses platform `BigInteger` arithmetic and SHA-512.
There is no external crypto dependency, Ed25519 JCA lookup, provider registration,
or host-wide resource exclusion.

The verifier requires 32-byte keys, 64-byte signatures, canonical point encodings,
`S < L`, and a nonidentity public key in the prime-order subgroup (`[L]A = 0`).
It checks the strict equation `[S]B = R + [H(R || A || message)]A` without
cofactor multiplication. This preserves the previous full public-key validation
policy. Legacy RFC 8410 SPKI parsing remains strict, with absent parameters.
Neither the FPTC signing bytes nor the legacy MD5-text signing format changed.

The arithmetic is variable-time and processes public verification inputs only.
Do not use this implementation for private-key operations or signing. Extended
Edwards coordinates avoid an inversion for each point addition; point decoding
performs the square-root and canonical-sign checks before scalar multiplication.

Tests cover RFC 8032, OpenSSL-generated envelope and legacy fixtures, JDK-generated
signatures across message lengths, and all 151 vendored C2SP/Wycheproof vectors
(88 valid, 63 invalid). See `src/test/resources/wycheproof/README.md` for provenance
and the vector digest. These fixtures are test-only resources.

The complete source-rebuild, corpus and device regression command is documented
in `../test/acceptance/README.md`. Keep functional verdicts and startup timing
budgets separate when comparing implementations.

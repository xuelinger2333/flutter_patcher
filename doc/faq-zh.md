# 常见问题

[English](faq.md) | **简体中文**

### 补丁为什么要冷启动才生效？

为了保证运行时的状态一致性。正在执行的代码与内存对象无法在运行期被安全地原地替换。补丁下载并校验完成后，当前进程会继续运行原有代码，直到下次 App 进程重新启动时才加载新补丁，避免单次运行周期内混用新旧两套代码逻辑。详见[工作原理](architecture-zh.md#设备上的生命周期)。

### 用普通 `flutter build` 打的包能接收补丁吗？

**不能。** 补丁只能安装在通过 `flutter_patcher build` 构建的基线安装包（宿主）上，因为热更新依赖定制引擎与内置的签名公钥（详见[工作原理](architecture-zh.md#宿主能接收补丁的安装包)）。已上线的普通安装包需使用 `flutter_patcher build` 重新构建并上架一次后，才能具备热更能力。

### 字节码策略会不会让 App 变慢？

**未打补丁时与普通 Release 包性能完全一致；打补丁后，仅被修改的函数由字节码解释器执行，其余未改动代码仍以原生机器码（AOT）运行。** 

对于常规 UI 与业务逻辑，性能差异几乎无感；但如果补丁修改的是高频计算的密集型热点代码，执行速度会比机器码慢。在 Android 端若对补丁性能极度敏感，可切换为 `so` 策略（代价是补丁包体积更大）。详见[两种补丁策略](architecture-zh.md#两种补丁策略)。

### 升级 Flutter SDK 版本之后怎么办？

升级 Flutter SDK 后必须重新执行 `build` 并上架新版本安装包。**补丁不能跨 Flutter 版本生效**——如果要继续为升级前的旧版 App 发补丁，仍需使用构建该旧版时的 Flutter SDK 版本（建议在 CI 中固定各历史版本的 Flutter 版本号，或通过 `--flutter-sdk` 指定）。

### 用户从应用商店升级 App 后，之前安装的补丁会怎样？

**自动失效并清理。** 每个补丁都严格绑定生成它时的基线构建号（`versionCode`）。用户升级到新版本 App 后，旧版本的补丁不再加载；若新版本也需要热更，需基于新版本的基线单独发布补丁。

### 可以同时维护多个线上版本并分别发补丁吗？

**可以。** 每个上架版本都有独立的基线快照和补丁序列。为旧版本修复 Bug 时，只需检出该版本对应的 Git Tag，修改代码后运行 `patch --version-code <旧版构建号>` 即可。详见[生产部署：发布流程](production-playbook-zh.md#发布流程)。

### 补丁会被第三方篡改或伪造吗？

**不会。** 客户端只加载经过你的私钥签名、且基线指纹（Scope）与当前安装包完全匹配的补丁。即使对象存储或 CDN 被攻破，攻击者也无法在没有私钥的情况下伪造合法补丁，或通过跨版本替换补丁实施降级攻击。详见[工作原理：安全模型](architecture-zh.md#安全模型)。私钥只保存在你的密钥目录中，请将其纳入备份（见[生产部署：配置存储](production-playbook-zh.md#配置存储)）。

### 如果发布的补丁本身有 Bug 导致启动崩溃怎么办？

**SDK 会在检测到启动失败后自动回滚至安装包自带的基线版本，并在本机拉黑该问题补丁**，确保用户不会陷入反复闪退的死循环。与此同时，你应当尽快在服务端执行[撤回补丁](production-playbook-zh.md#撤回补丁)或发布修复后的新补丁。详见[崩溃保护](crash-protection-zh.md)。

### 需要自己开发和部署后端服务吗？

**不需要。** 发布的补丁与清单全部是静态文件，任何支持 HTTPS 的静态文件托管服务（如 AWS S3、Cloudflare R2、阿里云 OSS 或 Google Cloud Storage 配合 CDN）均可直接使用。详见[生产部署：配置存储](production-playbook-zh.md#配置存储)。

### 支持 x86 模拟器或 32 位 Android 设备吗？

**不支持。** Android 端仅支持 `arm64-v8a` 架构（已覆盖目前市面上几乎所有在售及存量智能手机，也符合 Google Play 对 64 位的要求）。

### 应用商店政策允许使用热更新吗？

不同应用商店及不同行业（如金融、医疗、儿童应用等）对动态下发可执行代码的审核与监管政策各不相同。`flutter_patcher` 仅作为开源技术工具提供底层能力，上线前请自行评估目标分发渠道与所在行业的合规要求。

### 为什么在 Windows 上只改了一行代码，生成补丁时却提示“所有文件都被修改”？

这是由于 Git 换行符（`CRLF` 与 `LF`）不一致导致的字节比对差异。解决方法见[错误码与排障：常见问题](troubleshooting-zh.md#只改了一行-dart-代码却提示所有文件都被修改或报-patch_native_change)。
